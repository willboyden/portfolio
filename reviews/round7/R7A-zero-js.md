# R7-A: Zero‑JS / Graceful‑Degradation Review

## Lens score: 7/10

The site ships fully‑prerendered HTML + inline Emotion CSS — every page is a real document even with JavaScript disabled, there is no FOUC, and the branded 404 page carries full navigation. Content is fully present, all real‑link navigation works, and the skip‑link + `#main` target are correct. The failure modes are all *interactive affordances* rendered as inert controls when JS is absent: mobile navigation is completely lost on handhelds, search/filter and theme‑toggle do nothing silently, and on the live GitHub Pages deployment two footer links (`/rss.xml`, `/sitemap.xml`) 404 because they are hardcoded root‑absolute while the deploy script only rewrites bundle assets. The site degrades gracefully to a fully readable static shell — no data loss, no corrupted layout — but the interactive layer is effectively dead without JS.

## Out‑of‑lens observations (not counted in severity)

- **Wordmark monogram "AR":** `<span aria-hidden="true" class="css-a9muoh">AR</span>` precedes "William Boyden" on every page, local and live. The initials reference the placeholder persona Alex Rivera (the canonical alexrivera.dev domain) while the site identity is William Boyden. Visible even with JS disabled since it is plain HTML text. This is a content‑level bug, outside the zero‑JS lens, flagged for the content reviewer.
- **Search form `onSubmit={(e) => e.preventDefault()}`** (Writing.tsx:398): the form intercepts submission and performs client‑side search only; without JS the Enter key causes a full page reload doing nothing. Covered by R7A‑2 (search controls dead without JS) but noted here for completeness.

## Disposition recommendations

**Fix now (blocks / live‑visible regressions):**
- R7A‑3: Port the root‑absolute‑URL‑from‑BASE_URL pattern from the live commit to the local source; rebuild + redeploy to fix the live‑site 404 RSS/Sitemap links and the theme‑init/favicon asset references. This also resolves R7A‑4 (dist/404.html) as a side‑effect of the same pipeline change.
- R7A‑1: Add a static‑fallback mobile nav + noscript CSS so mobile users without JS retain full navigation. High user‑impact (handheld traffic).
- R7A‑4: Emit `dist/404.html` from the build pipeline so GitHub Pages serves the branded 404 with navigation instead of the generic "no site here" page.

**Fix in the next cycle:**
- R7A‑2: Gate search/tag‑filter chrome behind hydration or hide via noscript — improves UX for the no‑JS minority but does not affect content availability.
- R7A‑5: Remove or update the dev‑only noscript block so the review log accurately reflects what ships.
- R7A‑6: Convert back‑to‑top to an anchor or add noscript hide — low‑effort win, improves accessibility without JS.
- R7A‑7: Conditional render of the email `<li>` + move DRAFT comment outside the list — cosmetic cleanup, keeps the greppable marker without the empty bullet.

**Accept / document:**
- R7A‑8: Theme without JS = dark default + chrome‑page colour mismatch — recorded for maintainers; theme‑init.js is the intended resolution point.
- Out‑of‑lens AR monogram: flagged for the content reviewer; not a zero‑JS regression.
